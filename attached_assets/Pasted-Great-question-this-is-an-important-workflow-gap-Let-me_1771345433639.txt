Great question — this is an important workflow gap. Let me share my thoughts on how an MMP Cycle Close system could work:

The Core Problem:
Right now, when a new MMP is uploaded, there's no formal way to "close out" the previous one. Sites that were never visited just linger, and there's no accountability for why they weren't covered.

Proposed Design: MMP Cycle Close Workflow

1. Cycle Status Lifecycle:
Each MMP cycle would have clear states:

Active — the current working cycle, sites are being distributed and visited
Closing — a grace period where supervisors must account for uncovered sites
Closed — fully archived, no more actions possible
Only one cycle can be "Active" at a time (avoids confusion in the field)
2. How Closing Works:
When an admin uploads a new MMP or triggers a cycle close:

The system enters a "Closing" phase for the old cycle
All site visits still in "pending", "assigned", or "in progress" status automatically get flagged as Not Covered
Hub Supervisors get notified and must provide a reason for each uncovered site in their hub
Once all uncovered sites have reasons, the cycle can be fully closed
3. Reasons for Not Covered (supervisor selects from a list):

Not Distributed
CP Not Confirmed / Switched Off
Security Concerns
Access Denied / Area Inaccessible
Staff Unavailable
Weather / Natural Disaster
Budget Constraints
Time Constraints
Duplicate Site
Other (with a required text explanation)
Supervisors could apply reasons in bulk (select multiple sites, assign one reason) to save time.

4. Dashboard Impact:

Once closed, the old cycle's sites disappear from active cards and pages
Only the current active cycle shows on the dashboard
A "Closed Cycles" archive section lets admins review past cycles with full accountability data (which sites weren't covered and why)
5. Reporting Value:

Coverage gap reports per cycle showing % covered vs not covered
Breakdown by reason — helps identify systemic issues (e.g., if "Security Concerns" is frequent in certain hubs)
Hub-level accountability — which hubs consistently leave sites uncovered
6. The Two-Cycle Overlap Question:
I'd recommend against running two cycles simultaneously — it creates confusion for field staff about which sites to prioritize. Instead, the "Closing" phase gives a short window (maybe 2-3 days) for supervisors to account for gaps before the new cycle fully activates. This keeps things clean.
