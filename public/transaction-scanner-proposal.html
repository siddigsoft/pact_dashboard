01 — Proposal

Executive Summary

The PACT Transaction Screenshot Scanner transforms the manual, error-prone process of recording bank transfer receipts into a fully automated, auditable, and exportable digital workflow — directly inside the Command Center used by field teams every day.

Field finance staff currently photograph Bank of Khartoum transfer receipts and manually transcribe transaction IDs, amounts, recipient names, and dates into spreadsheets. This process is slow, introduces transcription errors, and produces inconsistent formats that complicate audits and reporting. The scanner eliminates this entirely.

Core value proposition: Upload a batch of receipt screenshots → AI extracts all data fields in seconds → Review in a structured table → Export a formatted Excel report with date subtotals, a grand total, and a Recipients Summary — all without touching a keyboard for data entry.
02 — Proposal

Problem Statement

Bank transfer reconciliation in Sudan's humanitarian sector faces a unique set of compounding challenges that no existing off-the-shelf tool addresses.

Bilingual Receipt Formats

Bank of Khartoum issues receipts in two completely different visual formats — the green تحويلات (transfers) style and the Bankak mobile style — both in Arabic script with English transaction IDs. Standard OCR tools fail on Arabic banking terminology.

Manual Transcription Errors

Transaction IDs are 10–20 digit strings. Amounts in Sudanese Pounds (SDG) can reach hundreds of millions. A single digit error causes reconciliation failures that take hours to trace and correct in the field.

Volume During Distributions

During site visit disbursements, a single finance officer may process 50–200 transfers in one day. Manual recording at even 3 minutes per receipt = 10 hours of data entry — impossible in a field setting.

Audit Trail Gaps

Paper-based records and informal WhatsApp groups as evidence create compliance gaps. Donors and auditors require structured, timestamped, deduplicated transaction records with recipient summaries.

03 — Proposal

Solution Overview

The Transaction Scanner is a module built into the PACT Command Center web application. It requires no installation — field staff access it from any device through a browser.

How the AI Pipeline Works

Image Upload & Compression

User drags & drops or selects receipt screenshots (PNG, JPG, WebP). Each image is automatically resized and compressed to 1024×1024 px at 82% JPEG quality before sending to the AI — reducing API costs and latency while preserving OCR quality.

Batched AI Vision Processing

Images are sent in batches of 5 to the AI vision API. The system tries Google Gemini 2.0 Flash first (fastest, cheapest). If Gemini's daily quota is exhausted, it automatically falls back to Meta Llama 4 Scout via Groq — ensuring near-zero downtime.

Structured Data Extraction

The AI extracts 9 fields per receipt: Transaction ID, Date & Time, From Account, To Account (full number), Recipient Name (Arabic supported), Mobile Number, Comment/Purpose, and Amount in SDG. Output is structured JSON.

Duplicate Detection

Extracted Transaction IDs are checked in real time against all other rows in the current session. Any row whose ID appears more than once is flagged in amber with a "Duplicate" badge — preventing double-counting before export or save.

Session Save & Export

Completed receipts can be saved to the database as a named session (e.g. "March North Darfur Batch") or appended to an existing session. Excel export generates a formatted multi-sheet workbook with date-grouped subtotals, a grand total, and a Recipients Summary sheet.

Supported Receipt Formats

Format A

Green تحويلات Style

Standard Bank of Khartoum branch transfer receipt. Green header with Arabic labels. Includes full account numbers, recipient name in Arabic, and QR code. Most common for large institutional transfers.

Format B

Bankak Mobile Style

Digital receipt from the Bankak mobile banking app. White background, English transaction ID at top, mixed Arabic/English fields. Common for staff advances and mobile money disbursements.

04 — Proposal

Innovation & Differentiators

The scanner is purpose-built for Sudanese humanitarian finance — not adapted from a generic tool. Each design decision reflects actual field conditions.

AI Innovation

Multi-Model Redundancy

Two independent AI providers (Google & Groq/Meta) with automatic failover. If one provider hits its daily quota mid-session, the system seamlessly switches — the user sees no interruption. Combined capacity: ~12,000 receipts/day.

Language

True Arabic OCR

Unlike standard OCR libraries that fail on RTL Arabic script, the AI vision models natively understand Arabic banking terminology. Recipient names, bank branch names, and purpose fields are extracted accurately in Arabic.

UX Design

Live Progress & Error Recovery

Each receipt shows its individual status (Waiting → Reading → Done/Error). Failed receipts show the error message and a Retry button. The whole batch never fails — only individual images that the AI cannot read.

Data Integrity

Real-Time Duplicate Detection

The same physical receipt is sometimes photographed twice. The scanner detects this automatically — any transaction ID appearing more than once is highlighted in amber with a warning banner, so duplicates are caught before they enter financial records.

Persistence

Session Memory & Append

Sessions are saved to a cloud database. If internet drops mid-scan, completed receipts are preserved. Users can return later, open any saved session, and add more receipts to it — perfect for multi-day distribution operations.

Reporting

Audit-Ready Excel Output

The export is not a raw data dump — it's a formatted, colour-coded workbook with date-grouped subtotals, a grand total banner, and a separate Recipients Summary sheet sorted by total paid. Ready for donor reporting on Day 1.

05 — Proposal

Data Collection Use Cases

The scanner integrates directly into PACT's existing field financial workflows. Below are the primary operational scenarios where it delivers the greatest impact.

Use Case 1 — Beneficiary Cash Disbursements

Context: Field coordinators in North Darfur, White Nile, and Kassala transfer cash to beneficiaries via Bank of Khartoum mobile transfers. Each transfer generates a receipt screenshot shared via WhatsApp.

Current process: Finance officer receives 80 screenshots per site visit → manually enters each into Excel → 4–6 hours of data entry → errors reviewed by supervisor → corrected entries uploaded to reporting system.

With scanner: Finance officer uploads all 80 screenshots at once → AI extracts all data in ~8 minutes → reviews the table for any flagged duplicates → exports formatted Excel → submits to supervisor. Total time: ~15 minutes.

Time saved: ~4 hours per site visit Error rate: Near zero Output: Audit-ready within 15 min

Use Case 2 — Staff Salary & Advance Payments

Context: Monthly salary transfers and field advance payments to data collectors, site supervisors, and drivers. Each payment generates a Bankak or branch receipt.

With scanner: HR/Finance creates a monthly session named "April 2026 — Staff Salaries". Transfers are done across multiple days. After each batch, receipts are scanned and appended to the same session. At month-end, the full session is exported as one consolidated Excel file with a Recipients Summary showing each staff member's total paid.

Use Case 3 — Operational Cost Verification

Context: Field operations involve daily expenses — transport, accommodation, fuel — paid via mobile transfer. These must be reconciled against approved operational cost submissions in the Command Center.

With scanner: Field officer scans all payment receipts from a field mission → exports by account to see payments per vendor → compares totals against the approved budget in the Command Center's financial module. The "Export by Account" feature allows generating a report for a single vendor in seconds.

Use Case 4 — Donor Financial Reporting

Context: Donors (USAID, EU, UNOCHA) require periodic financial reports listing every beneficiary payment with full bank details. The scanner's Recipients Summary sheet — with full account numbers, recipient names, transaction counts, and totals sorted by amount — maps directly to standard donor financial reporting templates.

Supports: USAID FFR format Supports: EU FACE reporting Supports: Internal PACT audit requirements
06 — Technical

Database Architecture

All scan sessions are stored in PACT's Supabase PostgreSQL cloud database — the same secure, RLS-protected infrastructure that underpins the entire Command Center.

Core Table: bank_transaction_scans

Receipt Object Schema (stored in receipts JSONB)

Each element in the receipts array follows this structure:

// Single receipt object inside receipts[] JSONB array
{
  "transaction_id":    "TXN20260304001234",   // Bank reference number
  "transaction_date":  "2026-03-04",           // ISO 8601 date
  "transaction_time":  "14:32:07",             // HH:MM:SS from receipt
  "from_account":      "1234 5678 9012",        // Sender account number
  "to_account":        "9876 5432 1098 7654",   // Full recipient account
  "recipient_name":    "أحمد محمد علي",          // Arabic name supported
  "mobile_number":     "0912345678",            // Recipient mobile
  "comment":           "مساعدة إنسانية",          // Transfer purpose
  "amount":            2550000.00              // Amount in SDG (numeric)
}

Security Model

Row Level Security (RLS)

PostgreSQL RLS is enabled on the table. The current policy allows all authenticated users access — suitable for the finance team's collaborative model. Role-specific policies (e.g. only the creator can delete) can be added without schema changes.

Supabase Auth Integration

The scanned_by field is automatically populated with the authenticated user's UUID from Supabase Auth. All saves are traceable to a specific PACT user account, providing a complete audit trail.

08 — Roadmap

Proposed Enhancements

The following improvements are proposed for the next development phase, ordered by operational impact.

High Impact

1. In-Cell Editing

Allow users to click any cell in the extracted data table and correct the value inline — without re-scanning the image. Particularly useful when the AI misreads a digit in an amount or truncates a long name. Changes would be reflected immediately in the export and session save.

High Impact

2. Receipt Image Preview on Hover

Show a thumbnail of the original receipt image when hovering over a table row. Enables instant visual verification of extracted data without switching windows. Critical for quality control when processing large batches.

Medium Impact

3. Beneficiary Matching

Cross-reference extracted recipient account numbers against the platform's beneficiary registry. Automatically flag transfers to accounts not in the approved list, and link confirmed transfers to their beneficiary profiles.

Medium Impact

4. Multi-Session Merge Export

Select multiple saved sessions (e.g. all sessions for a given month or MMP) and generate a single consolidated Excel report. Eliminates manual copy-paste between session exports for period-end reporting.

Medium Impact

5. PDF Certificate Generation

Generate a stamped PDF transfer certificate per session — similar to the platform's operational cost certificate — formatted for donor submission with PACT letterhead, authorised signatory field, and transaction table.

Enhancement

6. WhatsApp Webhook Ingestion

Integrate with a WhatsApp Business API endpoint so receipt screenshots sent to a designated group are automatically forwarded to the scanner API — eliminating even the upload step. Field officers simply send the screenshot to WhatsApp as they always do.

Enhancement

7. Currency Conversion & Exchange Rate Log

Integrate the platform's shared exchange rate service so SDG amounts are automatically converted to USD at the session date's rate. Dual-currency columns in the export (SDG and USD equivalent) would directly satisfy USAID reporting requirements.

Future

8. Offline Mobile Scanning (Flutter)

Extend the PACT Flutter mobile app to include an offline receipt scanning mode using the device camera. Extracted data is queued locally and synced to the cloud when connectivity is restored — critical for remote field locations with no internet.

USER MANUAL

Step-by-Step Guide

A practical guide for finance officers and field coordinators using the Transaction Screenshot Scanner in daily operations.

Manual — 01

Getting Started

Accessing the Scanner

Log into PACT Command Center

Open your browser and go to app.pactorg.com. Sign in with your PACT account credentials.

Open the Scanner

In the left sidebar, navigate to Payments & Finance → Transaction Scanner. Or go directly to /admin/transaction-scanner.

Prepare Your Receipt Images

Collect the receipt screenshots you want to process. They can be in any folder on your computer or directly from your phone. Supported formats: PNG, JPG, WebP. Recommended: screenshots at full phone resolution.

Tip — Preparing good screenshots: Make sure the receipt is fully visible and not cropped. Avoid blurry or dark images. If photographing a physical receipt (not a screenshot), use good lighting and hold the camera flat above the paper.
Manual — 02

Scanning Receipts

Uploading Images

You can add receipt images in two ways:

MethodHow ToBest For
Drag & Drop Select files in Windows Explorer / Finder, then drag them onto the dashed upload zone at the top of the page Large batches from a folder
Click to Browse Click anywhere on the dashed upload zone → a file picker opens → select one or many files Picking specific files
Add More After an initial batch is processed, click "Add more images" below the table or drag more onto the zone Adding to an in-progress session
No limit on batch size — you can upload 1 or 200 receipts at once. The system processes them 5 at a time in parallel. A batch of 60 receipts typically completes in 3–6 minutes.

What happens if the AI quota is exhausted?

The system uses two AI providers. If both have exhausted their daily free quotas, a banner will appear explaining this. Your uploaded images are remembered — you do not need to re-upload. Wait until midnight Pacific time (08:00 Sudan time the next day) and click Retry All.

Manual — 03

Managing Receipts in the Table

Deleting a Single Receipt

Each row has a small × button on the far right. Click it to remove that receipt from the current session. This is useful for:

  • Removing duplicate receipts (flagged in amber)
  • Removing receipts that failed OCR and belong to a different session
  • Removing a test or accidental upload
Note: Deleting a row from the table only removes it from the current view. It does not affect any previously saved session in the database.

Removing Duplicates

When the amber warning banner appears at the top of the table, duplicates have been detected. To resolve:

Identify the duplicates

Amber-highlighted rows with the "⊗ Duplicate" badge are the repeated entries. The Transaction ID column will show the same number in more than one row.

Delete the extra copy

Keep one row and click the × button on the other. The amber warning will disappear once each Transaction ID appears exactly once.

Clearing All Receipts

The trash icon button in the top-right bar (visible when rows are present and not processing) clears all receipts from the current view. Use this to start a fresh batch. This does not delete anything from the database.

Manual — 04

Session Management

Saving a New Session

Click the "Save" button

In the top bar, click Save (visible when receipts are extracted). The Save dialog opens.

Choose "New session"

The toggle at the top of the dialog should show "New session" selected (the default).

Give it a name (optional)

Type a descriptive name like "April 2026 — White Nile Disbursement". If you leave it blank, it saves as "Untitled scan" with the date and time.

Click "Save"

The session is stored in the cloud database and appears in the Saved Scan Records panel below the table.

Adding More Receipts to an Existing Session

Scan your new batch of receipts

Upload and process the new receipt images as normal. Wait until they all show "Done".

Open the Save dialog → choose "Add to existing"

Click Save → click the "Add to existing" tab. A list of your saved sessions appears.

Select the target session

Click the radio button next to the session you want to add these receipts to. The session's name, date, and current receipt count are shown.

Click "Add Receipts"

The system merges the new receipts into the selected session. Receipts whose Transaction ID already exists in that session are automatically skipped (no duplicates). A confirmation toast shows how many were added and how many were skipped.

Loading a Saved Session

In the Saved Scan Records panel, each row has a Load button. Clicking it restores all receipts from that session into the active table — allowing you to review, add more, or re-export.

Deleting a Saved Session

Click the Delete button in the session row. You will be asked to confirm. Deletion is permanent and removes all receipts stored in that session from the database.

Using "Export by Account" Filter

Click "Export by Account"

The filter dialog opens, listing all unique recipients found in the session with their account numbers, transaction counts, and totals.

Select the accounts you want

All accounts are pre-selected by default. Uncheck any you want to exclude. Use "Clear" to deselect all, then individually select the ones you need. The running total updates as you select.

Click "Export (N accounts)"

An Excel file is downloaded containing only the receipts from the selected accounts, still with all formatting, date subtotals, and the Recipients Summary filtered to just those accounts.

Manual — 06

Troubleshooting

ProblemLikely CauseSolution
Receipt shows "Retry" (red) Image was blurry, too dark, or cropped. AI couldn't read the fields. Click Retry. If it fails again, delete the row (×) and use a clearer screenshot of the same receipt.
AI quota exhausted banner Both Gemini (Google) and Groq (Meta) have hit their daily free limits. Wait until midnight Pacific time (08:00 Sudan time). Your uploads are saved. Click Retry All the next morning.
Export button does nothing Browser blocked the download, or no receipts are in "Done" status. Check that receipts show "Done". Allow downloads in your browser settings. Try a different browser (Chrome recommended).
Save fails with an error Internet connection dropped, or session expired. Check your internet. Refresh the page and try saving again. Your in-memory rows will be lost on refresh — save before refreshing.
Amount extracted incorrectly The AI misread a digit, especially in amounts with Arabic numeral format. Check the amount column. In-cell editing (roadmap feature) will allow direct correction. For now, note the correct value and adjust in the Excel file after export.
Duplicate banner appears The same receipt image was uploaded twice, or two receipts have the same transaction ID. Find the amber-highlighted rows. Keep one and click × to delete the other. The banner disappears automatically.
"Saved Scan Records" shows an error Database connectivity issue. Click the Refresh button in the Saved Scan Records panel header. If the error persists, contact the platform administrator.
