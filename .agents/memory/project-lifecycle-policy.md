---
name: Project lifecycle and reporting policy
description: Why retention, independent acceptance and honest reporting bases are separate in the Project module
---

Keep verified completion separate from a retention archive of unfinished work.
Allow deletion only for genuinely empty projects; use the existing Recycle Bin
for their complete header snapshot.

**Why:** Recovering a project header does not recover cascading child records.
The user approved improving the existing professional Project/Tasks workflow,
not introducing another project or recovery system.

**How to apply:** Never weaken linked-record deletion guards to make a large
project removable. Offer a reasoned retention archive instead. Financial sign-off
is a documented human reconciliation against current evidence, not a computed
guarantee of accounting balance.

Keep independent acceptance optional for ordinary legacy tasks. For tasks that
require it, Done means submitted, not accepted. Do not award the entire shared
task as each person's individual output.

**Why:** Simple tasks should retain their familiar flow while controlled work
has a meaningful independent review and person-specific evidence.

**How to apply:** Preserve reviewer independence and old-version evidence.
Reports must distinguish capture-time task state from recorded period events;
never invent historical performance before recording started. Capacity can
aggregate other-project hours for managers without exposing those project names
or private leave reasons.
